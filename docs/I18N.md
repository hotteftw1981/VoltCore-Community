# Internationalisation (i18n)

VoltCore Community is multilingual by design.

## Initial languages

- English (`en`)
- German (`de`)

English is the fallback language.

## Rules

1. New user-facing interface text should use translation keys whenever practical.
2. Translation files live in `app/locales/`.
3. Keys are grouped by feature, for example `nav.charge_points`.
4. A manual language choice overrides browser detection.
5. Without a manual choice, the browser `Accept-Language` header is used.
6. Unsupported languages fall back to English.
7. Technical identifiers, protocol values and stored OCPP data are not translated.
8. User-generated content is never translated automatically.

## Python usage

```python
from app import i18n

language = i18n.resolve_language(
    explicit="de",
    accept_language="en-US,en;q=0.9",
)

label = i18n.translate("nav.charge_points", language)
```

For Jinja templates, bind a translator to the current request language and expose it as `t`:

```python
context["language"] = language
context["t"] = i18n.translator(language)
```

Then:

```jinja2
<a href="/charge-points">{{ t("nav.charge_points") }}</a>
```

## Planned request integration

The Community web shell will resolve language in this order:

1. explicit/manual language cookie or saved preference;
2. browser language;
3. English fallback.

The language selector will be available in the user interface once the shared Community base template is introduced.
